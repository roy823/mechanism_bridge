## 11. 诊断：箭头种子为什么落后（事后分析，2026-10-04 07:21 EDT 记录）

- 起因：用户认为思路没有问题，要求检查实现。以下都是看过图 3/5 结果之后的事后分析，不属于事先写定的检验。
- 代码审查（`src/mechbridge/search_seeds.py`、`arrow_features.py`、`encounters.py`）：
  - 没有发现符号或方向错误：孤对电子残差和相遇取向打分都是"惩罚不对准"，并且被最小化；
  - 孤对电子项只对"孤对电子 d → 新键 d–a"这类箭头生效。箭头反向或打乱之后，这个条件基本不再满足，于是孤对电子项被关掉了。图 5c 中反向（+1.31）、打乱（+1.06）的增益与两项孤对电子消融之和（+1.15、+0.22）大致相当。
- 种子与参考 TS 的距离（`seed_quality.py` / `summarize_seed_quality.py`，35240f2；作业 44679473、44679670、44679753、44682267；不调用势能；本地 `docs/jctc/results/diagnosis/`）：
  - Coley（库能提出参考产物的 63 条）：各臂种子到作者 TS 的核心 RMSD 都约 1.5 Å，臂间差别不超过 0.04 Å；其中 33 条的孤对电子项从不生效，所以 Coley 上 arrows 与 bond_edits 的种子几乎相同，与图 4c 找回率相同（14.4% 对 14.3%）一致；
  - T1x（13 条，孤对电子项都生效）：完整箭头的种子更接近参考 TS（核心 RMSD 0.498 对 bond_edits 0.516 Å，10/13 条更近，Wilcoxon p = 0.021）。去掉孤对电子项、反向、历史种子都会让种子离 TS 更远。
  - 也就是说，箭头信息在几何上是有意义的：它把种子推向真实的 TS。
- **同一提案、同一随机数下的成对尝试**（`paired_attempts.py`，669fdc6，作业 44682535；C1、C2、C3、C6 合计 5794 对；本地 `docs/jctc/results/diagnosis/paired_attempts.json`）：

| 子集 | 对数 | IRC 连通：arrows / bond_edits（仅一方成功的对数） | 到达预测产物：arrows / bond_edits（仅一方成功） |
|---|---:|---|---|
| 孤对电子项生效 | 4097 | 1186 / 1327（492 / 633，p = 3×10⁻⁵） | 290 / 387（117 / 214，p = 1×10⁻⁷） |
| 孤对电子项不生效 | 1697 | 420 / 384（187 / 151，p = 0.057） | 53 / 53（25 / 25，p = 1.0） |

  - 分战役看，孤对电子项生效时差别最大的是 RGD1（到达预测产物 58 对 108，p = 7×10⁻⁶）；其次是生长体系（36 对 51，p = 0.011）和 Coley（105 对 131，p = 0.026）；T1x 接近（91 对 97，p = 0.49）。
- 结论：
  - 问题集中在一项设计：种子拟合里的孤对电子方向约束。它把种子在几何上拉近 TS（T1x），却让同一提案的 TS 搜索与 IRC 成功率明显下降；
  - 孤对电子项不生效时，箭头种子不比净变键差，还略好；
  - "箭头对搜索没有帮助"这个说法不成立。更准确的说法是：FP-JCTC-1 里孤对电子方向项的实现方式有害。
  - 可能的机制（我的判断，未验证）：
    - 这一项权重很大（÷0.3，键进度项是 ÷0.5），又没有键角保持项，拟合时会扭曲供体周围的取代基；
    - 种子的位移被归一化到固定长度后，用在"成键/断键"方向上的部分变少。
- 另外两点设计问题：
  - bond_edits 用的同样是箭头模板产生的提案，只是在构造种子时不看箭头，所以它不是"不含箭头"的对照。相对 geometry 的 3–4 倍提升，实际上来自箭头模板这个提案来源；
  - 图 3 的效率指标统计"与根相连的不同物种对"，奖励的是广泛（包括意外的）发现，而不是按机理找到预测产物。
